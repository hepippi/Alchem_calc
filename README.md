# Alchemy Factory 計算機

Steam ゲーム **Alchemy Factory** の生産計算サイトです。レシピ・時間・確率・熱量・研究効果などをすべて**インストール済みのゲームファイルから直接抽出**しているので、アップデートが来ても `tools/update.py` を1回実行するだけで最新データに追従できます。

現在のデータ: ゲームバージョン **0.5.4539**（Steam build 25991404）

## 機能

- **生産プランナー**: 複数の目標（個/分 または 設備台数）から、必要な設備数・原料・熱・燃料・肥料を計算
  - アイテムごとのレシピ切替（代替レシピ / 原料として扱う）
  - 加工方式ごとの設備切替（研磨機 ↔ 強化研磨機、坩堝 ↔ スタック式坩堝、錬金炉 ↔ 高性能錬金炉 など）
  - 研究レベル（工場効率・燃料効率・肥料効率・錬金技術・物流効率）を反映
  - 副産物・失敗品の再利用（例: 鋼インゴット失敗時の鉄インゴット、コークス失敗時の木炭）
  - 燃料・肥料の自給ラインも含めた計算（オプション）
  - 表 / ツリー表示、共有リンク、プラン保存
  - **薬草のみで完結（大釜を自動で併用）**: 外部投入を薬草だけに限定し、各アイテムを大釜と通常レシピのどちらで作るかを自動決定。優先順位は「設備スペース優先（通常設備＋大釜÷4。大釜は4段積み可能）→ 肥料ポイント → 薬草数 → 熱」と「肥料効率優先（肥料ポイント → スペース → 薬草 → 熱）」から選択。世界樹の葉は「使う／大釜の材料には使わない（既定）／使わない」。銅貨を大釜に入れない設定（既定オン）で、銅インゴット→銅貨300枚→大釜で値上げ→銅インゴットという薬草なしで増える循環を防ぐ（オフにすると木材系も薬草から作れる）。肥料系アイテムが目標のときは肥料収支（作った肥料÷消費した肥料ポイント）を表示。生産ライン（表・ツリー）のアイテムをクリックすると作り方の候補（自動／大釜（組合せ自動）／大釜の組合せ候補／各通常レシピ）がポップアップ表示され、各候補に固定した場合の設備スペース・肥料ポイント・大釜回数を現在との差付きで比較して選べる。選んだアイテムを固定して残りを再最適化する。同じアイテムを大釜と通常レシピに分割しない。必要な薬草ごとの栽培設備（栽培用地／苗床／世界樹の苗床）の台数も表示。燃料は対象外
- **大釜計算**
  - 錬成シミュレーター: 材料2〜3個から結果・計算値・製作時間・熱を表示。値バーで「この結果になる値の範囲」と前後のアイテムを可視化
  - 目標アイテムを指定すると、空き枠（または材料3）に入れれば目標になる材料を提案
  - 逆引き: 欲しい出力から材料の組合せを全探索（必須/除外材料、重複モード、カテゴリ絞り込み、価値順/近さ順）
  - 錬成表: 大釜で作れる47種の目標値・範囲・時間・熱の一覧
  - **薬草逆引き**: 薬草（亜麻〜世界樹の葉）だけを出発点に、大釜を何段も経由して目的のアイテムを作るルートを探索（材料は薬草と大釜の出力のみ）。標準の優先順位は 大釜回数 → 肥料ポイント → 薬草数 → 熱 → 時間（肥料ポイント・薬草数・熱・時間を優先する切替も可）、使う薬草の選択、段ごとの手順・必要薬草・合計時間と熱、最終段の別案、ルート一式をプランナーへ反映
  - 「使う」でその組合せをプランナーのレシピに設定（プランナー側でも「錬金釜」を選択可。未指定なら最安の組合せを自動選択）
- **アイテム図鑑**: 全アイテムの入手レシピ・使用先・1台あたりの処理量
- 10言語のアイテム名（ゲーム内翻訳をそのまま使用）、UI は日本語 / 英語

## 使い方（閲覧）

`site/index.html` をブラウザで開くだけで動きます（サーバ不要）。
公開する場合は `site/` フォルダをそのまま GitHub Pages などの静的ホスティングに置いてください。

## アップデート後のデータ更新

```bash
python tools/update.py
git add -A
git commit -m "Update game data to <version>"
git push
```

push すると GitHub Actions が `site/` を GitHub Pages に自動で公開します（数分で反映）。

ゲームのインストール先が既定と違う場合は `--game "D:\SteamLibrary\steamapps\common\Alchemy Factory"` を付けます。
アイコンの再書き出しを省略したいときは `--skip-icons`。

必要なもの: .NET 10 SDK、Python 3.10+（`pip install pefile pillow`）

## 仕組み

UE 5.7 の cooked アセットは「バージョン情報なし（unversioned）」形式で、読むには型情報（.usmap）が必要です。
通常はゲームを起動して UE4SS や Dumper-7 で吸い出しますが、本ツールは **exe 内に残っている UHT リフレクションテーブル**（`UECodeGen_Private::F*Params`）を静的解析して .usmap を再構築するため、ゲームを起動せずに済みます。

| ファイル | 役割 |
|---|---|
| `tools/dump_usmap.py` | exe から構造体・クラス・enum の型情報を復元し `.usmap` を生成 |
| `extractor/` | [CUE4Parse](https://github.com/FabianFG/CUE4Parse) を使った抽出ツール（DataTable → JSON、locres、アイコン PNG） |
| `tools/build_data.py` | 抽出結果を `site/data/gamedata.js` に変換 |
| `tools/update.py` | 上記を一括実行 |
| `site/calc.js` | 生産計算ソルバー（DOM 非依存） |
| `site/app.js` | 画面 |

主なデータソース: `DT_Enemies`（アイテム）、`DT_EnemyCrafting`（レシピ）、`DT_Buildings` + 設備ブループリント（設備・熱消費・速度）、`DT_PlantSeedConfig`（植物）、`DT_Improvements` / `DT_Attributes`（研究）、`Localization/Game/*/Game.locres`（各国語名）。

### 計算上の前提

- 錬金炉の失敗確率は期待値で計算（`ProductSequence` は同じ確率の決定論的な順序）
- `MaximumStack` が負のアイテム（原木・鉱石・遺物など）は分割素材。レシピの数量は 1/分割数 個として換算
- 苗床（肥料使用時）: 生産速度 = 60 × 肥料の栄養供給速度 × 工場効率 ÷ 1個あたり必要栄養（ベルト速度が上限）
- 大釜: 材料の `CauldronCost` を合計（同じ材料2つで×0.65、3つで×0.5）し、`CauldronMulti` が 0 でないアイテムのうち `CauldronTarget` が最も近いものが出力。ゲーム同梱の大釜レシピ4件（賢者の石・ルビー・サファイア・エメラルド）がすべてこの規則どおりになることを確認済み。製作時間の式も同4件の時間と一致。熱消費の式と2材料時の規則はコミュニティの検証値
- 薬草逆引きの肥料ポイント: 薬草を育てるのに必要な栄養（`DT_PlantSeedConfig` の `GrowthNutrientValue`）の合計。どの肥料で賄うかは問わない。リンドウ／リンドウの蜜、世界樹の葉／世界樹の核のように同時に収穫される場合は、1回の成長に必要な栄養を価値の比率で按分（リンドウ・蜜は各3,000、世界樹の葉は約29,849、核は約298万）。対象は栽培できる薬草のみ（幽暗キノコは除外）
- 薬草逆引きは「3材料→1出力」の有向ハイパーグラフ上の最短経路（一般化ダイクストラ／緩和の繰り返し）。木材・木炭は目標値が薬草3つの最小値より低いため薬草からは作れない
- 薬草のみモードは線形計画法（自作の2段階単体法）＋列生成で解く。大釜の組合せ（数十万通り）は双対価格と各アイテムの生産コストで有望なものだけを順次追加。段階1で設備スペースを最小化し（下位の項目は微小な重みで考慮）、段階2でスペースを上限固定して肥料ポイント→薬草→熱を最小化。分割が出たアイテムは主な生産方法に固定して解き直す
- 次の値はゲームデータに無く C++ 側にあるため、コミュニティの検証値を使っています: 加熱設備の待機消費（1熱/秒、坩堝は 0.4）、パラドックス坩堝に工場効率が効かない
- 初回実行時、CUE4Parse が Oodle 展開用 DLL を [OodleUE](https://github.com/WorkingRobot/OodleUE) のリリースから自動取得します
